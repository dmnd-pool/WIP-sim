# EMC2101-R component

This development component implements the EMC2101-R host configuration mode.
It is not a complete board or thermal model. Firmware acceptance remains
incomplete. Rust owns device state. C connects that state to the existing QEMU
I2C bus and virtual clock.

The source contract is the archived Microchip `DS20006703A` datasheet. Its
register tables, timing and fault behavior are the reference for the tests.
The exact Max schematic selects EMC2101-R-ACZL-TR. Fitted R36 is 10 kOhm from 3V3
to FAN_TACH. This selects host configuration, initial 0% drive and polarity 0.
R24 is not fitted. The device takes 10 ms to start. Auto-load EEPROM mode is not
selected by this board evidence and is not implemented.

The original PDF is retained at
`artifacts/files/document/open-emc2101-datasheet/EMC2101-Data-Sheet-DS20006703.pdf`.
Its SHA-256 is `1e5b0fc888d463b62f67f8d6e0c39cc9d48f7cf54ac4288af9a141cdddb1e3fb`.
The schematic observation and its parent hashes are in
`work/simulator/bitaxe/emc2101-strap-review-001.json`.

Inputs are explicit. Internal and external temperatures use eighths of a degree
Celsius. External open and short faults are distinct inputs. An open diode
returns 127 C and sets FAULT. A short returns 127.875 C without FAULT. Conversion
uses the datasheet's typical 3 ms internal and 21 ms external times. The inputs are
sampled at conversion start. These are functional timing assumptions, not
measured device calibration. Temperatures are quantized toward negative
infinity. The model has no claim of analog accuracy, ideality compensation,
noise, beta detection or board thermal coupling.

Table 4-2 limits external temperature codes to -64 C at the low end. Its upper
row says physical temperature at least 127.875 C maps to code 1022 (127.75 C).
The model follows that literal code and reserves 1023 for a short fault. This
one-eighth-degree discrepancy in the source table is retained explicitly.

The model implements single-byte SMBus pointer/write/read operations, aliases,
read interlocks, standby and one-shot conversion, programmable conversion rate,
temperature limits, critical-temperature hysteresis, fault queue, status clear,
alert masks, the one-time TCRIT unlock, direct fan setting and spin-up state.
STOP and repeated START preserve the pointer and registers. Power reset clears
volatile registers and starts the 10 ms delay. The C binding rejects general call
and addresses other than 0x4c. Its `restart` callback closes the byte phase without
a power reset. Current supply is a fixed explicit property in 3.0..3.6 V.

The tachometer takes actual rising and falling signal edges. Five edges span
one revolution for the specified two-pulses-per-revolution contract. The
nominal 90 kHz count follows the published `RPM = 5400000 / count` equation.
No connected tachometer gives the reset value 0xffff. Writing a fan request does
not produce any tachometer edges or measured speed. Edge silence after a
measurement expires after the 16-bit count interval. The supported low-speed
saturation mode returns 0xffff. Unspecified low-speed counter-wrap behavior in
other clock modes produces a model fault and 0xffff; it is not valid RPM evidence.

The C binding exposes an input named `tach` and an active-low output named `alert`.
It currently has no fan waveform or mechanical fan attached. A traced
`fan_request` is a command, not RPM. PWM waveform generation, DAC load response,
fan dynamics, lookup-table control, averaging, analog compensation, EEPROM
autoload, SMBus timeout and Alert Response Address remain implementation work.
Writes that enable missing LUT, averaging or compensation modes fail visibly.
Reserved accesses, read-only writes and multi-byte transfers also fail with a
model fault; the exact undocumented hardware responses are not established.

Every virtual deadline must be processed. An advance that skips more than 256
pending sensor events stops conversion and records a model fault. It cannot
claim an intact measurement trace. QEMU schedules each pending deadline.
Migration and snapshots of this state are not implemented.

The diagnostic original-factory fixture uses an explicit 27 C internal test input,
an open external diode and no fan tachometer. The temperature is declared test
data, not measured board telemetry. The factory is expected to retain real
fault behavior. The ASIC thermal diode, power regulator, INA260 and board
thermal response still need their own models and evidence.
