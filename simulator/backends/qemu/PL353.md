# PL353 development model

This model is incomplete. It does not identify the NAND part on an exact S9 controller board.

The Rust module is `axi-iic/src/pl353.rs`. The existing backend static library contains both peripheral modules. Their state and interfaces are separate. `md-sim-pl353.c` binds the Rust state to QEMU memory, time and IRQ interfaces. The flash storage engine is the existing QEMU 9.2.2 NAND component. Its original member and provenance are under `vendor/qemu-9.2.2/`. The build extracts and verifies that member from the original archive, then records the small QEMU API port and its output hash. It does not create another flash storage engine.

The controller has separate command and data phases, split five-byte addresses, x8 transfers, end commands, chip-select release, ready-event state, a virtual busy interval, interrupt clear/enable, reset, and four 512-byte Hamming ECC results. Invalid sizes, unsupported register/mode requests, incomplete address phases and busy reads return an explicit memory-transaction error. The backend records that error. Exact command/end-command/address-count tuples are checked before bus effects. Data direction must match the current command. A second program confirm requires a new SEQIN command. The ECC command registers accept only the standard command values used by the archived driver; other values fail instead of reading back as supported.

The `md-sim-s9-nand-fixture` machine adds this controller at `0xe000e000` and its aperture at `0xe1000000`. The exact archived DTB SHA-256 `550c87818cb0db41c00a8351dc4ac7b5dce5bf6d5336539c6951163ebf3cb62a` specifies these addresses and GIC SPI18. Its isolated decoded evidence is `work/simulator/qemu-s9/dtb-inspection-001/`. The base S9 development machine keeps its prior device set.

The fixture uses the existing QEMU NAND ID `ec:da`, 256MiB of data, 2048 data bytes plus64 spare bytes per page, and64 pages per erase block. Other IDs are rejected. Storage starts erased and stays private. An optional backing file must hold exactly131072 complete pages, including spare bytes. A data-only file is rejected because the legacy component would keep its spare data only in memory. This is an explicit controller test fixture, not a substitute identity for the unresolved physical S9 chip. The original archived SPL and U-Boot bytes are unchanged when tested against it. Such an experiment cannot pass exact-board acceptance.

File backing uses `-drive if=none,id=md-nand,...` and `-global md-sim-pl353.drive-id=md-nand`. The child NAND owns that backend. Legacy `if=mtd` belongs to the original Zynq board's SPI devices and must not be reused for this NAND fixture.

Read/program/erase delays are currently functional baselines of25us/300us/2ms. These values agree with typical Micron AACWP data-sheet figures, but do not calibrate the generic fixture or an actual board. The reset delay is a5us model baseline. Full bus-cycle timing is not implemented. The selected cycle register is retained for inspection; it does not yet change timing. This limitation must remain in results.

The current scope excludes x16, SRAM, other interfaces/chip selects, random data input, ONFI parameter pages, on-die ECC features, DMA, and migration. The generic fixture avoids a false on-die ECC claim. Exact Micron support and physical board mapping remain separate work. The QEMU9 NAND engine has additional upstream limits; its presence does not make all commands compatible.

The separate `nand-timing.patch` delays the existing storage callback until the virtual program/erase deadline. Pending page data has its own snapshot, so status reads cannot corrupt it. NAND RESET cancels an unfinished operation. A controller-only reset preserves the chip's busy interval. The atomic abort is a development contract; it is not measured physical behavior during power loss. Storage changes stay in C because these callbacks and private state belong to the existing C NAND component. The controller state stays in Rust. The derived patch also bounds page writes, fixes spare-only pointer arithmetic, uses exact byte ranges for full backing files, and propagates failed backing reads instead of returning old data as a successful page.

Seven PL353 Rust tests cover split command addressing, reset and ready timing, command/data ordering, unsupported behavior, invalid end commands, and all4096 single-bit ECC locations. C ABI tests run with UBSAN and ASAN. LeakSanitizer cannot run in the current environment because ptrace is denied. The compiled qtest uses independent literal bus transactions and real storage bytes; no firmware message is manufactured. Backend016 passes normal storage and delayed-operation checks. Backend018 passes the delayed-operation check after storage bounds fixes. Full file-backed boundary and restart tests are separate; see their retained result before claiming that capability.

The current final storage checks are `work/simulator/qemu-s9/nand-storage-008/` and `nand-storage-009-ubsan/`. Both pass complete264MiB byte comparisons after program and erase, spare and final-file boundaries, invalid write rejection, NAND bitwise program behavior, and two clean process restarts. The latter uses the actual C backend with UBSAN and fatal sanitizer errors. `nand-timing-qtest-005/` and `nand-timing-qtest-006-ubsan/` pass delayed program/erase and reset-abort transactions. Physical power-loss behavior and exact board identity remain unverified.

The compiled timing test was run with:

```sh
target/debug/examples/s9_backend_qtest work/simulator/qemu-s9/backend-build-018 work/simulator/qemu-s9/nand-timing-qtest-003 nand-timing
```

Original SPL, SD U-Boot, FIT loading, both CPUs, kernel and ramdisk execution are retained in `work/simulator/qemu-s9/spl-nand-fixture-001/`. That development run is not an exact-board pass. Its NAND scan fails. With strict command validation, `spl-nand-fixture-002` retains a kernel timeout caused by a command with zero address-cycle bits. The model does not silently replace those bits with the expected five cycles.

Old build stores001–017 had duplicate objects removed only after full hashes and byte comparisons against retained build018. The exact restore map is `work/simulator/qemu-s9/duplicate-cas-cleanup-001/relocation-map.json`. Copy or import mapped objects before replaying one of those historical stores. Do not use hardlinks. Unique objects, original archives, binaries and logs remain preserved.
