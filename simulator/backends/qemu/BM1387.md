# BM1387 chain development contract

This path is incomplete. It implements powered chip identification,
address assignment, selected register state, timed serial replies, and
functional nonce search. Firmware mining acceptance remains incomplete.

The reference archive SHA-256 is
`dc5f58721f596d2fc36b50d5049461264986ac339c4b4ff4d383749b98f3a363`.
The source revision is Braiins `74b80e7a6d862e49355b79b45302842bdc58c116`.
The [source review](../../../work/simulator/bm1387-source-review-001.json)
pins the driver, command codec, GPIO, null-work and FPGA sources.

The explicit development profile has three chains. Each chain has 63
BM1387 chips and 114 cores per chip. The oscillator is 25 MHz.
The exact silicon core address map remains unvalidated. The archived `lib.rs` says
the 114 core addresses are not consecutive within the 128-address space.
Its SHA-256 is
`1eaa099131265a837c3e3ebbe03674fe22193206573a69fa87e08c035d522a6e`.
The nonce layout therefore requires an explicit core address list for
each chip. A count of 114 must not select addresses 0 through 113.
Tests with consecutive addresses are labelled synthetic fixtures.
The [vendor reference map](bm1387-reference-core-map.json) now provides
addresses 0–56 and 64–120. This is an inference from the pinned Bitmain
test program's receive mapping and its 114 counted positions. The map
records its source hashes and limits. It does not prove an exact board
or silicon stepping. The reference development chain consumes this map.
The starting serial divisor is 26: 8,640 nanoseconds per bit.
Divisor 1 gives 640 nanoseconds per bit. The identity reserved byte
is `0x90`, from the archived driver's register test vector. This vector
does not prove a production silicon reset value or stepping.
Each link has a 1,024-byte reply resource bound. Physical per-hop delay
and chip buffer depth remain unknown.

The serial adapter uses one start bit, eight data bits with the low bit
first, and one stop bit. It samples bit midpoints. Framing errors,
breaks, partial packets, checksum errors, queue limits, reset and baud
changes have explicit state. The separate S9IO UART retains its archived
16-sample HDL behavior.

The serial component has versioned saved state. It preserves the active
transmit and receive frames, pending output, pin levels and event deadlines.
Restore validates queue bounds, bit indices, line state and future times.
An incompatible version or impossible state fails before it is installed.
Enqueue and frame start check the full frame's time range. A clock overflow
cannot leave a byte halfway through transmission. The component replay test
checks both serial rates at every bit boundary and sampling phase.
This device state is not a complete chain or board snapshot. Those must also
preserve decoders, chip state, work budgets, peer pins and all event queues.

Both peers advance on one Rust timeline. This prevents a delayed QEMU
callback from collapsing earlier serial edges into one instant. Events
strictly before an FPGA edge reach its input first. At the same timestamp,
both peers sample the previous output levels. No host time or hash-rate
cap changes these bus clocks.

The UART can skip divider clocks between registered sample pulses when
its pins, synchronizer and FIFOs cannot change. The packet receiver can
also wait between bytes without a callback on every FPGA clock.
The optimization stops before each sample, input edge or pending bus
operation. Tests compare every skipped clock with ordinary clock-by-clock
execution, including low pins, bad stop bits, BREAK, CRC checks and IRQs.
The [055 compiled comparison](../../../work/simulator/qemu-s9/uart-skip-compiled-comparison-001.json)
matches all 16,191 prior ASIC and S9IO events, in order, with exact timestamps.
A further optimization skips unchanged transmit state while the UART FIFO
is full. Its long-packet tests check all 150 work bytes and queued commands
against archived vectors. The
[compiled burst regression](../../../work/simulator/qemu-s9/uart-skip-compiled-comparison-003.json)
matches all 23,192 events between builds 055 and 056.

PIC power outputs at `0x55`, `0x56`, and `0x57` connect to chains 6, 7,
and 8. Active-low reset uses output GPIO bits 9, 10, and 11. These bindings
follow the archived driver and observed Linux GPIO bank bases. The machine
is named `md-sim-s9-bm1387-development`. It remains a reference profile;
the selected FPGA bitstream's full correspondence is not established.

Reset or power loss clears addresses, partial packets and replies. The
inactive command starts sequential address assignment. Address zero is
an assigned address after the first assignment. Filter and miscellaneous
register writes retain their exact values. Unwritten values remain unknown.
The archived source describes PLL readback bit 31 but does not establish
its meaning or lock timing. PLL status therefore returns an explicit model
error. The optional [temperature fixture](TMP421.md) implements bottom-bus
pin routing and timed I2C transfers to an explicit TMP421 input.
Other pin routing, divergent per-chip baud rates, unresolved I2C behavior
and other registers remain explicit errors.

The functional work path uses the guest's actual midstates and header
tail. Each core has its complete 19-bit nonce space. Chip and core address
bits remain separate. New work replaces the current search. Already queued
results retain their serial timing. Reset or power loss cancels the search.
The source describes core startup with the gate bit and nBits bit zero.
The model opens one core per chip for each such packet. These packets
still contain work; they do not create a nonce or a startup success.
Core-opening order follows the recorded map. This order is a development
policy, not measured silicon behavior.

One run-owned budget limits all three chains to 10,000 host-computed
hashes per wall second by default. The budget accepts lower positive
rates that fit the clock range. The machine property `hash-cap-hps`
selects the cap before startup. Active chains take turns, weighted by
their enabled cores. Idle time, reset and job replacement create no burst
credit. Virtual polling uses a separate interval on each chain. Serial,
boot and protection clocks keep their own periods.

Each computed-hash event now carries its shared grant number and elapsed
monotonic host time in nanoseconds. The budget samples this time when it
admits the computation, before SHA-256d runs. It does not sample trace delivery
time. The independent auditor checks consecutive grant numbers across all
chains, the first interval, every later interval, and the process wall bound.
Legacy traces without these fields keep an explicit unavailable result for
this check. A whole-run hash count cannot establish per-hash spacing.
The separate `s9_asic_audit rates RUN NEW_REPORT` check requires a complete
trace with actual grant timestamps. It fails when those timestamps are absent.

The search computes one SHA-256d result per grant. Each chip's programmed
ticket mask filters that result, including the fixed 32-bit condition.
Filter readback matches the programmed state. The default has no filter override.
With ticket mask zero and 10,000 H/s, the expected ASIC response interval
is at least 429,496.7296 seconds. A short native-filter run therefore does
not establish fresh-work mining acceptance. A recorded low-rate adaptation
is still needed for practical end-to-end tests.

The optional fixed-filter policy reduces only the leading fixed zero-bit
count. Its default is 32. A value from 1 through 31 is an adaptation.
The policy keeps every guest-programmed ticket bit in its original
position. Register `0x18` reads that actual ticket value. The fixed
condition has no guest register; the QEMU property and run manifest record
the adapted value. The policy survives chip reset. Reset still clears
the ticket register and requires the guest to program it again.
Expected share intervals use the intersection of this filter and the
pool target. No adaptation supplies a nonce or bypasses hashing.
The runner requires an explicit `adapt-fixed-filter-bits` option and a
backend build that supports this separate contract.

Trace kind 10 records a computed nonce. Its extra field contains the work
ID in bits 0–7, midstate index in bits 8–15, and actual ASIC filter match
in bit 16. Kind 11 records a received job and its enabled core count.
Neither event means that a pool accepted a share.
Kind 12 records a model stop after an explicit error. Received bytes and
computed hashes before that error remain in the trace. This event is
not an ASIC reply or a successful command.

The optional `md-sim-bm1387-packets/1` trace records the actual receive
bytes at each apply, rejection, serial fault, model stop or reset boundary. Each
packet records its link, virtual time and boundary kind. The following
state event records the same boundary. The trace also retains serial
reply bytes, pin state, job state and every computed hash. It omits
duplicate receive-byte events and serial output pin edges. It does not
claim a complete bus trace. A partial packet has no record until its
boundary occurs. The runner records truncation separately.
The hash auditor rejects mixed raw and compact streams. It checks
packet checksums, completion boundaries and all retained hashes.

Build 058 executes the archived 2022 bosminer startup path. The retained
prefix contains 158 applied work packets and 3,539 computed attempts.
The independent midstate audit checks all retained attempts. None passes
the ASIC filter. These are core-startup packets, not fresh pool jobs.
The run times out, exceeds its trace limit, and disables board power.
The cause of shutdown is still under investigation. See the
[audit](../../../work/simulator/qemu-s9/sd2022-bm1387-console-011/asic-hashes.json)
and [execution result](../../../work/simulator/qemu-s9/sd2022-bm1387-console-011/result.json).
No full-board or mining pass follows from this diagnostic.

Use a new output directory for another run. The
[report](../../../work/simulator/qemu-s9/bm1387-qtest-004-ubsan/assessment.json)
checks independent power and reset inhibition through actual PIC and GPIO
connections. The test uses QEMU's test clock. It does not execute firmware.

The first original firmware run found a separate C binding defect. Two
clock reads during one pin callback gave different times under normal
CPU execution. The resulting phase error stopped the machine. The fix
captures one timestamp for advancement and the pin change. Its firmware
reruns pass that point. The
[054 diagnostic](../../../work/simulator/qemu-s9/sd2022-bm1387-console-005/assessment.json)
executes archived firmware through startup of all three PIC controllers.
It ends at the CPU limit before chip enumeration. The trace has no PIC
protocol errors or undefined PIC reads. This remains a failed diagnostic.
Work execution and board acceptance remain open.

The [055 firmware diagnostic](../../../work/simulator/qemu-s9/sd2022-bm1387-console-008/assessment.json)
receives identification replies on all three chains. Chain 6 assigns all
63 addresses, programs PLL value `0x006d0511`, changes its serial rate,
and reads back ticket mask zero. The other chains are still assigning
addresses when the CPU limit stops the run. The script does not finish;
this is not a successful boot or mining result.

The [056 diagnostic](../../../work/simulator/qemu-s9/sd2022-bm1387-console-009/assessment.json)
completes setup on all three chains and sends its first core-startup work.
The [packet audit](../../../work/simulator/qemu-s9/sd2022-bm1387-console-009/asic-packets.json)
retains the actual bytes and their parent hashes. That backend stops on
its explicit unimplemented-work error. The newer Rust work integration
passes fresh-header oracle, serial, replacement, rate and reset tests.
Its compiled firmware rerun is pending.
