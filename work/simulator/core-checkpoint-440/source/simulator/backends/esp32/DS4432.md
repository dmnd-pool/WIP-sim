# DS4432 current DAC development model

The Rust model is `sar-adc/src/ds4432.rs`. The device converts a register code to output current. It does not report an ASIC voltage or simulate a complete regulator.

The reference is Maxim's DS4432 datasheet, revision 0, December 2008, pages 2, 3, 6 and 8. The publisher serves it at [Analog Devices](https://www.analog.com/media/en/technical-documentation/data-sheets/ds4432.pdf). The browser provider supplied text and page images. The original PDF bytes have not yet been saved and hashed. This reference gap remains explicit.

The two volatile registers are `0xf8` and `0xf9`. Each has seven magnitude bits and one sign bit. Zero magnitude gives a high-impedance output. The nominal equation is `I = 0.997 V / RFS * code / 16`. The model takes each full-scale resistor and the supply voltage as explicit inputs. Zero resistance means an unconnected pin. Current results use nanoamperes, rounded toward zero. Positive values source current. Negative values sink current. The documented output-voltage limits are checked. An unconnected pin, an invalid supply or a voltage outside those limits gives an unspecified result, never a valid measurement.

The bus model supports single-byte writes and register-pointer reads with repeated START. STOP and controller-only reset preserve the registers. Power loss clears them. A supply transition outside the operating range uses an ideal reset assumption; actual brownout thresholds and ramps are not modeled. The power-on pointer is not specified in the reference; direct reads before pointer selection fail with a model fault. Reserved addresses, extra burst bytes and extra reads also fail with visible faults. These choices are development limits, not measured hardware responses to undocumented commands. Nominal current changes at the acknowledged register write. Analog settling, leakage, thermal drift, supply-ramp behavior and accuracy tolerances remain incomplete. The reference gives no settling bound used by this implementation.

The published 80 kΩ, `0xaa` example independently checks the nominal output of 32.714 µA. Other tests cover both channels, signs, pointer transactions, reset, power loss, compliance limits and rejected operations. Unit tests do not establish compiled QEMU or firmware acceptance. The C adapter uses QEMU's existing I2C bus and explicit device properties. Its fixed address is 0x48; general calls are rejected. A repeated START preserves registers and the pointer. The physical regulator connection remains incomplete. Compiled test and original-firmware results are recorded separately in `work/simulator/bitaxe-progress.md`.

Exact archived source members are in `work/simulator/bitaxe/power-reference-001`, with their parent and member hashes. The selected Max schematic uses R14 = 4.99 kΩ, R15 = 3.32 kΩ and R16 = 80 kΩ. The matching ESP-Miner v2.14.2 driver uses R14 = 4.75 kΩ. This disagreement remains unresolved. The model must not turn a requested firmware voltage into measured telemetry or silently replace the board resistor value with the driver's constant.
