# ESP32-S3 I2C development model

The Rust controller is `sar-adc/src/i2c.rs`. It shares the existing native static library with the SAR module. This keeps one Rust runtime in the QEMU link. The two modules have separate state and C interfaces.

The model uses the archived ESP32-S3 TRM version 1.8, chapter 27. The PDF hash is `4484bf8a69035ec42a731c58c64ada6fbd1f1618c5559409f134d9ea083f444f`. The register map and opcodes differ from the archived QEMU `esp32_i2c.c`. That existing model also performs the whole command synchronously and lacks required FIFO bounds. It cannot supply the S3 controller unchanged. The C binding reuses QEMU's existing I2C bus and slave interfaces. It does not implement a second bus protocol stack.

The implemented path has two independent master controllers, each with 32-byte TX and RX FIFOs and eight command registers. It supports 7-bit address transmission, repeated starts, byte writes, byte reads, receiver NACK, STOP, and END followed by another command sequence. Slave responses come from the attached QEMU bus. The first integration has no slaves. A missing slave must return a NACK. It cannot count as a working display, voltage controller, fan controller or sensor.

The byte delay uses the programmed clock source, fractional divider and SCL low, high and wait periods. START and STOP use their programmed periods. This is byte-level timing. It is not electrical calibration or a model of individual SDA and SCL transitions. Configuration synchronization is explicit. The controller preserves register readback, FIFO pointers, command-done bits, interrupt masks, clear operations and FIFO thresholds. Reset ends an active transaction and cancels pending timer actions. A repeated TRANS_START write refreshes execution from command zero, as TRM section 27.4.14 specifies. It replaces the pending timer and retains the FIFO and bus state. The real firmware uses this sequence during STOP recovery after a missing-device NACK.

The archived QEMU bus keeps the current slave list during its original START operation. This can send a changed-address repeated START to the prior slave. `i2c-reselect.patch` adds an explicit operation which rescans the requested address without sending STOP or releasing bus ownership. Existing QEMU callers retain their original API. The S3 binding uses the new operation. Each attached slave must implement or be reviewed for the optional repeated-START callback. DS4432 aborts only its byte phase and preserves its pointer and current registers. It also rejects general-call address zero. This does not establish correct behavior for other unreviewed QEMU slaves.

Unsupported modes stop with a recorded model fault and an error interrupt. These include slave operation, 10-bit addressing, non-FIFO access and least-significant-bit-first transfer. Electrical arbitration, clock stretching, system clock and reset inputs, APB RAM windows, timeout state machines and active FIFO starvation recovery are incomplete. Empty TX or full RX while a command is active stops with an error. A clock change while active also stops with a visible fault. These limits are not test exclusions for a completed target.

The default clock sources are the TRM's nominal 40 MHz crystal and 17.5 MHz internal clock. Physical clock accuracy is not measured. VM migration is disabled. A QEMU machine reset clears this controller, but the system peripheral-reset register is not yet connected.

Nine controller behavior tests check the TRM write sequence, programmed timing, real address and data NACK, repeated-start reads, END continuation, FIFO limits, unsupported modes, synchronization, reset, refreshed STOP timing and deadline overflow. These run with the existing SAR crate checks. They do not pass a firmware gate. `i2c-master.patch` adds the C binding and two devices at the documented addresses with interrupt sources 42 and 43. Build and original firmware evidence are recorded separately.

The source-derived reference files in `work/simulator/bitaxe/i2c-reference-002` have a member hash manifest. The first extraction attempt requested a nonexistent SoC header and stopped. Its partial output is retained separately; it is not a complete source manifest.
