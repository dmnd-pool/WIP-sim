# INA260 development model

The contract is TI SBOS656C, revised December 2016. The archived PDF is
`artifacts/files/document/open-ina260-datasheet/ina260.pdf`, SHA-256
`5160ed4af198b093e541beb3fe5f1048f00233fa23cd4f4822391acad9f94dcf`.
The matching Max schematic has fitted INA260AIPWR with A0 and A1 grounded,
which selects address 0x40. VBUS senses incoming VIN. Current flows from VIN
through IN+ to IN- and VIN_M. It does not measure ASIC core voltage.
Exact schematic observations are in
`work/simulator/bitaxe/ina260-wiring-review-001.json`.

Rust owns the volatile registers, pointer, two-byte bus transactions, conversions,
averaging and alert state. C connects the existing QEMU I2C bus and virtual timer.
VIN and current are mandatory explicit inputs. Firmware settings do not create
measured voltage, current or power. The diagnostic attachment is separate from
a physical PSU, regulator and ASIC load model.

Each current conversion precedes its bus-voltage conversion. The output set
updates only after the selected number of samples. Power is the mean of each
sample's absolute current times voltage, not the product of the two means.
Alert comparisons use the unaveraged samples at their conversion deadlines.
Only the highest selected alert function acts. Conversion-ready may also assert
the pin. Configuration restart, one-shot operation, shutdown, 40 microsecond
recovery, reset, read-clear and latch behavior have separate state.

This is an ideal, partial component. It samples each physical input at the start
of its conversion and truncates fractional output units toward zero. It does not
model the analog integration window, noise, shunt heating, tolerance or supply
ramps. Initial power-up starts the default conversion without an added delay;
only the documented shutdown recovery gets 40 microseconds. Accepted input
current is limited to the documented continuous range of minus15 to plus15A.
Transient overcurrent and thermal damage are not modeled. The math-overflow
flag is implemented. The datasheet does not specify overflow output bits, so
the model saturates power and records a model fault. Such a run is incomplete.

The datasheet has conflicting latch-clear rules. Section 8.3.3.2 says a
configuration write can clear a latched alert; Table 6 says only a Mask/Enable
read clears it. The model follows section 8.3.3.2 and records a model fault when
that conflict affects an active latch. Transparent alerts remain until a later
non-alert comparison. A search of TI's public product and support pages found
no resolving erratum. This behavior needs independent physical confirmation.

Two read bytes form one snapshot. Read side effects occur at the first byte.
An incomplete configuration word does not commit; it restarts the old conversion
and records a model fault because that timing is not specified. Extra bus bytes,
unknown registers and writes to read-only registers fail visibly. Reserved
configuration and mask bits retain their documented read values. Diagnostic
counters survive a component reset; they are evidence counters, not guest data.

The C attachment currently has fixed address straps and initial electrical
properties. Rust also has a timed input-update interface for a future connected
electrical model. There is no default attachment. SMBus alert response,
SCL-low timeout, high-speed filters and dynamic address straps remain incomplete.
The byte-level QEMU bus does not expose SCL edges. General-call and alert-response
addresses do not receive a false normal-register ACK. Migration is disabled.
No physical board, calibration or mining gate follows from component tests.
