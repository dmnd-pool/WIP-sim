# TMP421 development contract

This component is incomplete for release. Its attachment is an explicit
fixture. It does not establish the sensor fitted to an exact hashboard.
The [profile](s9-tmp421-reference.json) records all fixed inputs and limits.
Temperature values come from those inputs. They are not measured telemetry.

The register contract uses [TI SBOS398C](https://www.ti.com/lit/ds/symlink/tmp421.pdf),
revised May 2012. The PDF was consulted online. A complete archived copy
and its hash remain required evidence. The model implements sequential
conversions, range changes, paired reads, channel selection, shutdown,
one-shot operation, reset, and diode and supply faults. Registers retain
state. Conversion time is separate from the mining rate.

The timing profile is a development choice: 50 microseconds before startup,
115 milliseconds for conversion, and a 125-millisecond channel slot.
Resistance correction disabled selects half those channel times.
Channel selection takes effect at the next sequence. Range and correction
settings are sampled at channel start. Physical temperature is sampled at
completion. Open and supply faults remain recorded if they occur during
a conversion. The ideal diode input uses an ideality factor of 1.008.
These choices are not calibration results.

The fan recovery auditor checks these fixed inputs with a separate arithmetic
conversion schedule. It joins the applied ASIC command, completed bus transfer,
and paired sensor replies. A change to extended range can leave the previous
normal-range bytes until the next channel conversion completes. TI SBOS398C
page 11 describes this delay. The firmware can interpret 65°C as 1°C during that
transition. The audit retains that actual reading. It rejects an old format
after the next conversion, different inputs, fault flags, unconfirmed writes,
or changes to the conversion policy. Repeating the same configuration write
does not renew the transition window. Reset of ASIC registers does not reset
the sensor; a power cycle does. This test validates the declared reference
timing only.

The pinned QEMU source was reviewed before implementation. Its TMP421
file has SHA-256
`98901934bddf85f4c44f4cc771f31bcf2e98e03e944eb0bcddac3e99e1834799`.
The [source inspection](../../../work/simulator/qemu-temperature-source-001/references.json)
retains that file. It has no ADC conversion clock or one-shot execution.
Its channel-enable behavior is incomplete. A Rust component shares the
existing ASIC timeline directly. This avoids another device bridge and
permits the required timing and fault tests. No CPU emulator is added.

The BM1387 controller fields follow the archived Braiins driver at commit
`74b80e7a6d862e49355b79b45302842bdc58c116`.
The I2C driver file SHA-256 is
`a43eab9c698d244eb9e5bbab9fd7c417db4f7c81f39c2fb9246c2a3e3fec9b88`.
The sensor driver file SHA-256 is
`cefdfd8f9673ada7661cbaff4e8cb41c60c2992d07249545839a726c60af8239`.
The shared address helper SHA-256 is
`5cb55313d402cca4d61d1c03d6097a9e807298ea6e8a50335aa33b3cf8135ff1`.
Its [retained source](../../../work/simulator/braiins-i2c-source-006/references.json)
defines an inverted operation bit: even addresses read; odd addresses
write. This ASIC control register does not use the conventional I2C
wire direction bit. Original run 026 exposed the previous wrong assumption.
Build 064 and its sensor fixture regression used that wrong assumption.
Those results do not validate the native sensor path.
See the [retained reference texts](../../../work/simulator/braiins-monitor-source-005/references.json).
Register `0x20` carries flags, an eight-bit bus address, a sensor register,
and data, in that order. The high bit reports a pending transaction.
The fixture attaches to chip position 61 on the bottom bus.

The controller's 100 kHz clock, zero reset word, and busy readback are
explicit reference policies. A write uses 29 clock slots. A read uses 39.
These include byte acknowledgements and one slot per bus condition.
They do not claim physical pin waveforms. A write during a transaction
fails explicitly. A pin-routing change during a transfer also fails
explicitly, because its physical behavior remains unknown.
An unknown slave address stops with an unresolved NACK
behavior error. It does not return invented data. ASIC reset aborts a
transaction but preserves the separately powered sensor. Power loss
resets both.

The optional temperature input plan supplies up to 256 timed external input
changes. Each event has `at_ns` and the same `inputs` fields as the profile.
Times must increase, start after zero, and use absolute virtual nanoseconds.
The JSON input is limited to 4096 bytes. Conversion and bus completion take
effect before an input edge at the same time. A short diode or supply fault
thus remains visible even if the firmware reads after the input recovers.
The plan continues during power loss. Reset of the whole virtual timeline
replays the frozen plan. ASIC register reset does not restart it.

The development bundle option `temperature-plan=JSON_FILE` requires the
explicit sensor fixture and a backend with the plan startup check. Preparation
retains the original JSON bytes and their hash. It records the canonical
events in the adaptation manifest and the QEMU arguments. The QEMU property
is `md-sim-s9io.temperature-input-plan`. These external input changes do not
alter the guest's thermal thresholds or create a protection success message.

Archived S9 firmware runs now exercise numeric temperature changes through
the real BM1387 sensor transaction path. The
[105°C test](../../../work/simulator/qemu-s9/temperature-hot-174/temperature-audit-177.json)
checks readback and continued operation. The
[115°C test](../../../work/simulator/qemu-s9/temperature-dangerous-174/temperature-audit-177.json)
observes the native shutdown message, all three power cuts, restored 65°C
readings and resumed hashing. Both plans change the external input at 150s
and restore it at 180s. Native thresholds remain 100°C and 110°C.

The audit joins each guest I²C request to its CRC-checked controller replies.
It checks the paired high and low sensor bytes, including fault flags.
Repeated readback of one completed controller transaction is one measurement.
PIC power output records must precede matching ASIC input changes. The two
real-time timestamps need not be equal. Older backend166 traces fail this
stronger ordering test and must retain their older, limited audit scope.

when repeating them:

work/simulator/ssh-target-177/release/examples/s9_asic_audit temperature work/simulator/qemu-s9/temperature-dangerous-174 work/simulator/qemu-s9/temperature-dangerous-174/temperature-audit-177.json

Both native runs also pass independent fresh-work verification. Eight selected
blocks pass separate Core imports and node restarts. See the
[hot session](../../../work/simulator/qemu-s9/temperature-hot-174/regtest-audit-174-session-0.json),
[recovered dangerous session](../../../work/simulator/qemu-s9/temperature-dangerous-174/regtest-audit-174-session-11.json),
and [Core result](../../../work/simulator/bitcoin-core/temperature-dangerous-174-audit174-session11-job1/block-acceptance.json).
These are reference-environment tests with the recorded fan-monitor adaptation.
They do not validate an exact physical hashboard or its protection circuit.

The [ADC validity fault and manual recovery audit](../../../work/simulator/qemu-s9/temperature-supply-invalid-manual-recovery-180/temperature-audit-179.json)
passes for all three reference chains. The fault starts at150s of QEMU time;
the input returns at180s. The original firmware logs sensor errors. The guest
then uses its original service command to restart the miner. The verifier
requires a new process, actual power cycles, healthy paired reads and resumed
computation. Linux uptime and QEMU time have separate origins in the report.
Four fresh blocks from the two native mining sessions pass Core acceptance
and restart. See the [recovered-session result](../../../work/simulator/bitcoin-core/temperature-supply-invalid-manual180-audit179-session9-job1/block-acceptance.json).
This test does not establish automatic recovery or a protective shutdown.
An ADC validity fault does not model loss of all sensor power.

The thermal plant, physical wiring, all sensor variants, analog bus faults,
and exact controller error behavior remain required work. The fixture must
not establish an exact-board thermal-protection or full-board pass.
