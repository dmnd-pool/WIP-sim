## Enumeration boundaries

The collection preserves vendor API responses, public directory lists, release feeds, and pinned repository trees.
These indexes establish what each source exposed at collection time.
They do not establish that all deleted releases, private repositories, or regional mirrors were found.
Discovery records remain leads until their claims are verified.

## Internal image checks

ESP image hash anomalies recorded: 2.
Read [the exact image anomaly records](../catalog/parts/open/esp-image-hash-anomalies.jsonl).
Some old factory bootloader images have a flash-configuration header that differs from the header covered by the stored appended hash.
The original bytes remain unchanged. This observation alone does not establish a boot result.

Read [the container check report](container-integrity.json) for ZIP CRC and gzip-stream checks on the root-collected subset.
Eleven Bitdeer updates have valid gzip streams followed by installer-script trailers.
The [Bitdeer layout index](../catalog/parts/emerging/bitdeer-image-layouts.jsonl) preserves their offsets and component hashes.

The [download failure index](download-failures.csv) separates rate limits, unavailable URLs, transfer errors, and saved alternatives.
Failure counts refer to records and attempts, not unique unavailable firmware releases.
A superseded attempt can remain indexed after another URL supplies the same payload.
